# freeform-typing

お題の無いローマ字タイピングゲームを作るためのリポジトリ。

## どんなゲームか（構想）

ふつうのタイピングゲームは「打つべき文」が画面に出る。このゲームではお題を出さず、プレイヤーが自由に日本語の文を打つ。
打った文は形態素解析と埋め込み（文や単語のベクトル）で評価され、得点のルールはカードとして途中で選んで足していく（デッキ構築型ローグライク）。
ルールの例:

- 固有名詞が入っていれば加点
- 前に打った文から意味が遠い文ほど加点
- 文の中の名詞どうしが意味的に離れているほど加点
- 前の文としりとりになっていれば倍率

序盤は自由に打つだけで、カードを足すほど「得点のために何を打つか」を考えるようになる。埋め込みの点はおまけのバフの位置づけ。

公開版: https://ryokaringumi.github.io/freeform-typing/

## いまあるもの

- **ゲームの試作版**（`index.html`、`src/game/`）: 下の「試作版の決めごと」のとおりに一通り遊べる。点の数え上げ・打鍵の反応・効果音などは「演出と手触り」。
- **評価のテストベンチ**（`bench.html`、`src/bench.ts`）: 形態素解析と埋め込みが人の予想どおりに振る舞うかを確かめる台。ゲームのタイトル画面と画面の下の一行の「評価のテストベンチ」から開ける。
  - kuromoji.js の解析結果（表層形・品詞・細分類・原形・読み・発音、固有名詞の印）
  - transformers.js による文の埋め込み（既定は日本語専用の `sirasagi62/ruri-v3-30m-ONNX`、画面で切り替えられる）と、直前の文・過去の全文とのコサイン類似度／距離
  - 文中の名詞どうしの距離の行列、前の文とのしりとり判定、ひらがな化しての再解析
  - 履歴の JSON 入出力、得点ルールを JS の関数で書いて全件で試す欄

すべてブラウザの中で動く（サーバー無し）。埋め込みモデルは初回に Hugging Face Hub から読み込み（既定の設定で約 44 MB）、以後はブラウザのキャッシュから読む。

## 試作版の決めごと

一度作って遊んでみるための仮の決めごと。理由と一緒に書く。

### 入力

- ふつうの入力欄に打ち、Enter で送る。ローマ字入力の IME で漢字に変換してよい。
  理由: ひらがなだけの文は kuromoji の区切りが大きく崩れる（小さい仮名の前で切れて長い未知語になり、固有名詞も消える）。変換してもらうのが一番素直で、打ち方は標準のローマ字入力のまま変わらない。
- IME の変換確定の Enter では送らない（`isComposing` / keyCode 229 を見る）。
- 漢字もカタカナも入っていない 6 文字以上の文を送ると「漢字に変換した方が正しく読める」と出す。
- 打っている文が使う拍を、入力欄の上の縁にいつも出す（上の帯の「残りの拍」の棒にも、使う分を縞で重ねる）。残りより長い文は送れず、入力欄に残る（赤くなる）。
- 打鍵数と、最初の打鍵から送るまでの秒数を数えて内訳に出すが、**点には入れない**。理由: 「同じ文は同じ点」を守るため。速さを点にするかは遊んでから決める。

### 点の計算

- 1 文の点 = **基本点 × 倍率**（Balatro の チップ × 倍率 と同じ形）。
  - 基本点 = 読みの音の数（拍）＋「点」のカード。拍は kuromoji の読み（カタカナ）で数え、小さい ャュョァィゥェォヮ は前と合わせて 1 拍、ッ・ー・ン は 1 拍。読みの取れない語（辞書に無い漢字、英字のまま）は数えない。1 文の拍に上限は無い（下の「拍の予算」で区切る）。
  - 倍率 = 1 ＋「倍率＋」のカード、そのあと「倍率×」のカードを掛ける。小数は 1 桁、点は四捨五入で整数。
- **同じ文は同じ点**（決定的）。ただし前の文・このラウンドの文を見るカードは、その並びも含めて同じなら同じ点。埋め込みは 1 文ずつ推論する（バッチにするとパディングで値が揺れうるため）。
- このランで前に送ったのと同じ文は 0 点。理由: 決定的なので、高い点の文を 5 回送るだけで済んでしまう。
- 送るたびに、効いたカードも効かなかったカードも、何を見てどう効いたかを全部出す。解析の区切り（品詞・固有名詞の印）も並べて出す。プレイヤーが「解析にはこう見えている」を学べるように。
- 内訳は数え上げの演出の中で順に見せる（下の「演出と手触り」）。数え上げの途中でも次の文を打って送れる（送ると残りを飛ばす）。

### ラウンドとゲート

- 1 ラウンドは **拍の予算 100** と **7 文** で区切る（`src/game/rules.ts` の `MORA_BUDGET`・`HANDS`）。送った文の拍が予算から引かれ、残りより長い文は送れない。英字・数字など読みの取れない字は、基本点には入らないが予算からは 1 字 1 拍引く（`cards.ts` の `budgetCost`。読めない字で予算を使わずに名詞を並べられないように）。制限時間は無し。
  - 理由: 前は「1 ラウンド 5 文・1 文 30 拍まで」で、名詞・カタカナ語・動詞などの数で増えるカードは拍の上限の外でも伸びたので、長い文を打つほど得だった（集計では、カードを見ずに一番長い文を打つだけで 9 ラウンド先まで進めた）。拍の予算で区切ると、長い文は点が大きいぶん予算を早く使うので、比べるのは **1 拍あたりの点** になる。内訳と結果の画面には「何拍・1 拍あたり何点」を出す。
  - 文の数の上限も残すのは、短い文をたくさん並べて、文ごとに効くカード（しりとり・遠い名詞など）を重ねすぎないようにするため。7 文は、15 拍ほどの短い文でも予算を使い切れる数。
  - 時間で区切る案は取らない: お題が無いので「何を打つか考える」時間が要る。
  - 決め方の集計と、ほかの案（拍の数を平方根などで頭打ちにする、制限時間）を取らなかった理由は [docs/balance.md](docs/balance.md) の「長い文ほど得になる問題」。
- 合計がゲートに届いた時点でクリア（残りは使わない）。拍か文を使い切って届かなければ終わり。
- ゲート: ラウンド 1〜8 が 70, 100, 160, 250, 360, 520, 750, 1100 点（前は 70, 100, 170, 280, 450, 700, 1000, 1450）、その先は 1.5 倍ずつ（50 点単位に丸め）。ラウンド 2 のゲートは予算と同じ 100 点なので、カード無しでは予算をちょうど使い切らないと越えられず、その先はカードが要る。難易度はこの表（`src/game/rules.ts` の `GATES`）と予算だけで変えられる。数値は集計（[docs/balance.md](docs/balance.md)）で決めた: ふつうの文を打つだけなら 2〜4 ラウンド、カードに合わせて文を選ぶと 6〜10 ラウンド進める形。
- クリアすると、まだ持っていないカードから 3 枚を無作為に見せ、1 枚選んで足す（取らずに進むこともできる）。最初はカード無し（拍の数だけが点）。
- 初めて見るカードは「はじめて」の札が付き、くわしい説明が開いた状態で出る（見たカードはブラウザに覚える）。手持ちのカードは、乗せると説明の札が出て、押すと大きく開く。
- ラウンドの終わりはすぐに画面を重ねず、最後の文の内訳を読めるようにしてから「カードを選ぶ」ボタン（Enter でも押せる）で進む。押しっぱなしの Enter で読み飛ばさないよう、ボタンは出てから 0.3 秒置いて押せるようになる。
- カードを選ぶ画面では、数字キー 1〜3 でも選べる。

### カード

| 名前 | 種類 | もと | 効果 |
| --- | --- | --- | --- |
| 名のあるもの | 倍率＋ | 形態素 | 固有名詞 1 つにつき 倍率＋1（3 つまで） |
| 名詞あつめ | 点 | 形態素 | 名詞（数・代名詞・非自立・接尾を除く、重複なし）1 つにつき ＋4 点 |
| 品詞のパレット | 倍率＋ | 形態素 | 品詞の種類（記号・フィラーを除く大分類）が 3 を超えた分、1 種につき 倍率＋0.5（2 種分まで） |
| 動詞の連鎖 | 倍率＋ | 形態素 | 動詞（自立）1 つにつき 倍率＋0.4（3 つまで） |
| カタカナ語 | 点 | 形態素 | カタカナだけで書かれた名詞 1 つにつき ＋10 点 |
| 長文の心得 | 倍率× | 形態素 | 読みが 40 拍以上の文は 倍率×1.5 |
| しりとり | 倍率× | 形態素 | 前の文の最後の仮名で始まると 倍率×2（判定はテストベンチの「一致（厳密）」と同じ） |
| 十七音 | 倍率× | 形態素 | 読みがちょうど 17 拍なら 倍率×3 |
| 話題転換 | 倍率＋ | 埋め込み | 前の文から遠いほど 倍率＋1×t |
| 新境地 | 倍率＋ | 埋め込み | このラウンドの前の文のどれからも遠いほど 倍率＋1.5×t（一番近い文の t） |
| 遠い名詞 | 点 | 埋め込み | 文の中で一番遠い名詞の組が遠いほど ＋12×t 点 |

- 数で増える倍率のカード（名のあるもの・品詞のパレット・動詞の連鎖）には上限がある。理由: 長い文ほど数が増え、基本点（拍）と倍率の両方が長さで伸びて、拍の予算の中でも長い文ほど 1 拍あたりの点が上がるため。上限は短い文（15〜20 拍）でも届く高さにしてある。
- 「長文の心得」は前は「拍の上限 30 → 60」だった。1 文の上限を拍の予算に替えたので、長い文に倍率を付けるカードにした（取った人だけが「長い文で一気に稼ぐ」を選べる）。
- 埋め込みの点は「おまけ」にとどめる: 倍率なら最大＋1・＋1.5、点なら最大＋12 で、形態素のカード（固有名詞 3 つで＋3、しりとり×2 など）より上がりにくくしてある。集計では、埋め込みのカードの寄与は点の 2〜3 割（3 枚とも持って寄せたときで 4 割弱）。
- カードの数値は `src/game/cards.ts` の `TUNING` に、埋め込みの「遠さ」の測り方は `src/game/distance.ts` の 2 つの関数（`sentenceFarness`・`farthestNounPair`）にまとめてある。測り方を差し替えるときはこの 2 つだけを変えればよい。
- **埋め込みの t の出し方**: ruri-v3-30m の cos は関係の無い文どうしでも 0.7〜0.85 あたりに詰まるので、生の cos は点にしない。基準の文 24 個・語 24 個（`src/game/refs.ts`、話題がばらけるように選んだふつうの文と語）を用意し、「前の文から見て、基準のうち何個よりこの文の方が遠いか」の割合を t（0〜1）にする（順位で引き伸ばす）。試した範囲では、言い換えの文は t=0、同じ話題は 0.1 前後、関係の無い文は 0.4〜1 にばらついた。基準と同じ文字列は数えない。
- 埋め込みが測るのは話題の近さで、反対の意味（好き／嫌い、熱い／冷たい）は遠くならない。単語の埋め込みはとくに当てにならない（宇宙と味噌汁が近め、など）。どちらもカードの説明に書いた。
- 埋め込みのモデルは読み込みに時間がかかる（初回 約 44 MB）。読み込みが終わるまで埋め込みのカードは候補に出さないので、その間も形態素のカードだけで遊べる。推論は Web Worker（`src/embed-worker.ts`）で行う（送るたびの推論で画面の処理を止めないため）。

## 演出と手触り

- **打鍵**: キーを押すたびに入力欄が小さく光って沈み、短いクリック音が鳴る（変換中は少し柔らかい音）。Backspace は別の音と赤みの反応。
- **IME**: 変換中は入力欄の縁が黄色になり「変換中」の札が出る。確定すると緑に光って確定の音。変換確定の Enter では送らない（決めごとのとおり）。
- **送る**: 打った文が入力欄から上の舞台へ飛び、低い音。
- **数え上げ**（Balatro の点の数え上げにならった）: 文と解析の区切りが出たあと、「基本点 × 倍率 = この文」の箱が動く。まず拍の数を数え上げ、次に効いたカードを 1 枚ずつ、手持ちの列のそのカードを光らせながら、内訳の行を出して基本点（青）・倍率（赤）に足していく。倍率× のカードは箱が跳ねて粒が飛ぶ。最後にこの文の点を数え上げ、ラウンドの点の棒へ足す。効かなかったカードの行は最後にまとめて薄く出す。
- **ゲート到達**: 棒が緑に変わって光り、音と粒。**ラウンドクリア**: ファンファーレと紙吹雪、帯。**ゲームオーバー**: 下がる音と帯の揺れ、結果の画面（越えたラウンド・最高・合計・一番点の高かった文）。
- **カードを選ぶ画面**: 3 枚が順に配られ、乗せると浮く。選んだカードが光ってほかは沈み、手持ちの列に落ちてくる。
- **飛ばす**: 数え上げの途中で、空の Enter・舞台や箱を押す・次の文を送る、のどれでも最後の状態まで飛ばす。演出の途中で操作が止まることは無い。
- **設定**（右上の「設定」）: 音の on/off と音量、演出（おまかせ＝OS の「視差効果を減らす」〔prefers-reduced-motion〕に従う／ふつう／減らす）、数え上げの速さ（ふつう／速い）。ブラウザに覚える。（打っている文の拍は、拍の予算を入れたのでいつも出す。前は設定で出し入れできた）演出を減らすと、動き・浮かぶ文字・粒・紙吹雪を止め、点はすぐ最後の値を出す。
- **音**はすべて WebAudio でその場で合成している（外部の音素材は使っていない）。

### 画面の配置

- ページではなくゲームの画面として、ビューポート全体（100dvh）を使い、ページはスクロールしない。はみ出しは舞台・手持ちの列・履歴の中だけで流す。
- 横長: 上の帯（ラウンド・ゲートまでの棒と残りの点・残りの拍の棒・残りの文・このランの合計・「これまでの文」・設定）／中央の舞台（打った文・解析の区切り・カードごとの判定）と、その下の点の箱（基本点 × 倍率 = この文）／右の手持ちのカードの列（背が足りれば下にこれまでの文）／下の入力欄。ラウンドの終わりのボタンは入力欄の場所に重なる。
- 縦長・幅の狭い画面: 残りの拍の棒は帯の 2 段目に横いっぱいに出る。幅 520px 以下では、残りの文を点の列ではなく数で出し、「ゲートまで」の札を出さない（1 字ずつ縦に折れるため）。手持ちのカードは帯の下の横の列（高さは画面の 3 割まで）になり、舞台・点の箱・入力欄が続く。これまでの文は上の帯のボタンから開く。
- 長い文は舞台の中で折り返し、長さに応じて字を一段ずつ小さくする。語が 28 を超える文は、解析の区切りを閉じておき、判定の行を先に見せる。
- 字の大きさは `theme.css` の `--fs-base`（`clamp(15px, 0.6vw + 0.9vh + 2px, 34px)`。1366×768 で約 17px、1920×1080 で約 23px、2560×1440 で約 30px）で決まり、ほかはすべてその何倍か（rem）で書いてある。
- タイトル画面（遊び方の 5 つの段: お題は出ない・文が点になる・拍には限りがある・ゲートを越える・カードでルールを足す）と、ゲームオーバーの画面（越えたラウンド・最高・合計・送った文、ラウンドごとの点とゲートの棒、一番点の高かった文、手持ちのカード）がある。

### ルールの評価の見せ方

- 送った文ごとに、手持ちのカード全部に **効いた・あと少し・効かず** の札を付けて舞台に並べ、上に枚数のまとめを出す。手持ちの列のカードにも同じ札と入った値が付く（数え上げが終わってから）。
- 「あと少し」は、少し直せば効いた、が言える場合だけ出す: 十七音で拍の差が 3 以内（「あと 2 拍」）、長文の心得で 40 拍まで 3 拍以内、品詞のパレットで種類がちょうど閾値（「あと 1 種」）、しりとりで濁点だけ違う、埋め込みのカードで t が 0 より大きいのに丸めで 0 になった。判定は `src/game/ui/verdict.ts`（見せ方だけで、点は変えない）。
- しりとりのカードには、次の文の始めの音（「次は『ム』から」）を出す。
- カードの面には、いちばん大きく「何をすると得か」の一文（`src/game/ui/card-guide.ts` の `goal`）、その下に効果の一行。例文はカードの関数にその場で通して、実際に何が入るか（例「東京で山田さんに会った」→ ＋2）を出す（数値を変えても例がずれない）。

### 画面の作り（見た目を直しやすくするため）

- 色・字の大きさ・配置の幅・角の丸み・動きの長さは `src/game/ui/theme.css` の CSS 変数だけで変えられる。部品ごとの CSS はこの変数を使う。
- 部品ごとにファイルを分けてある: 上の帯と手持ちの列（`ui/hud.ts`・`hud.css`）、数え上げの舞台と点の箱（`ui/scoring.ts`・`stage.css`）、入力欄（`ui/input.ts`・`input.css`）、カード（`ui/cards-view.ts`・`cards.css`）、重ねる枠（`ui/overlay.ts`・`overlay.css`）、内訳の表と履歴（`ui/breakdown.ts`・`breakdown.css`）、タイトルとゲームオーバー（`ui/screens.ts`・`screens.css`）、カードの判定（`ui/verdict.ts`）、カードの「何をすると得か」と例文（`ui/card-guide.ts`）、設定（`ui/settings-view.ts`）。画面全体の配置は `base.css`。
- 音は `fx/audio.ts`、動きの道具（待ち時間・飛ばす・浮かぶ文字・粒）は `fx/motion.ts`・`ui/fx.css`、設定は `fx/settings.ts`。ゲームの流れは `main.ts`、点の計算は `cards.ts`、ラウンドの決めごとは `rules.ts`。

## 手元で動かす

```sh
npm install
npm run dev      # 開発サーバー（ゲームは /freeform-typing/、テストベンチは /freeform-typing/bench.html）
npm run build    # dist/ に出力
npm run preview  # ビルド結果を確認
npm run sim -- --runs 300 --label after   # 点の釣り合いの集計（tools/sim/、結果は tools/sim/out/）
```

集計は、ゲームと同じ採点の関数に `tools/sim/corpus.ts` の文例を通し、打ち方とカードの取り方の方針を変えて多数のランを回す。`--tune '{"haiku":{"x":2}}'` でカードの数値を、`--gates 70,100,...` でゲートを、`--budget 100`・`--hands 7` で拍の予算と文の数を差し替えて試せる（`--budget 0` で予算なし）。埋め込みは初回に Hugging Face Hub からモデルを読み、ベクトルを `tools/sim/.cache/` に残す。結果の読み方と、いまの数値を決めたときの前後の表は [docs/balance.md](docs/balance.md)。

kuromoji の辞書は `npm run dev` / `npm run build` の前に `node_modules/kuromoji/dict` から `public/dict` へコピーされる（リポジトリには含めない）。

ヘッドレスで確かめる口として、ゲームのページは `window.__game`（`state()`・`phase()`・`submit(text)`・`cost(text)`（その文が使う拍）・`pick(i)`・`start()`・`toTitle()`・`restart()`・`skip()`・`verdicts()`・`animating()`・`idle()`・`embState()`・`settings()`・`setSettings({...})` など）、テストベンチは `window.__bench` を出している。
